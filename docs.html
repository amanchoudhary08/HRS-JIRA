TaskFlow

A full-stack collaborative project and task management application with real-time updates via Server-Sent Events.

Go 1.22 PostgreSQL 16 React 18 TypeScript 5 Vite 5 Docker Compose SSE JWT

1 Project Overview

TaskFlow is a collaborative project and task management tool. It allows teams to organise work into projects and track individual tasks through a Kanban-style board with drag-and-drop support and live real-time updates.

  • Register and log in with email/password (bcrypt hashed, JWT sessions).
  • Create projects and invite collaboration by assigning tasks.
  • Create tasks with title, description, status, priority, assignee, and due date.
  • Drag tasks between Kanban columns (Todo → In Progress → Done).
  • Filter tasks by status and assignee with URL-persistent filters.
  • Real-time updates via Server-Sent Events — no polling, no WebSockets.
  • Dark mode that persists across sessions via localStorage.
  • Paginated project and task lists.

6.2 main.go — Entry Point

Wires together all components and manages the server lifecycle.

  1. Reads env vars: DATABASE_URL, JWT_SECRET (required), API_PORT.
  2. Opens PostgreSQL connection pool: max 10 open, 5 idle, 30 min lifetime.
  3. Calls waitForDB() — polls db.Ping() every second for up to 30 s.
  4. Runs goose.Up(db, "migrations") — applies pending SQL migrations automatically.
  5. Constructs app struct with db, jwtSecret, logger, broker.
  6. Registers all routes via app.routes(mux).
  7. Starts HTTP server: ReadTimeout 10s, ReadHeaderTimeout 10s, IdleTimeout 60s. No WriteTimeout — SSE connections are long-lived.
  8. Waits for SIGINT/SIGTERM, then graceful shutdown with 10 s context. 
type app struct {
    db        *sql.DB       // shared postgres connection pool
    jwtSecret []byte        // HMAC secret for JWT signing
    logger    *slog.Logger  // structured JSON logger (stdout)
    broker    *eventBroker  // in-memory SSE pub/sub
}

6.4 middleware.go — HTTP Middleware

a.auth — JWT Bearer verification

  1. Reads Authorization header, expects Bearer <token>.
  2. Parses JWT with HMAC-SHA256 against a.jwtSecret.
  3. Extracts user_id and email claims, validates UUID format.
  4. Queries DB: SELECT id, name, email FROM users WHERE id=$1 AND email=$2 — revoked/deleted accounts can't reuse tokens.
  5. Stores authUser in request context under userKey.
  6. Returns 401 at any failure step.

a.cors — CORS headers

Sets Access-Control-Allow-Origin: *, Allow-Headers: Authorization, Content-Type, Allow-Methods: GET, POST, PATCH, DELETE, OPTIONS. Returns 204 to OPTIONS preflight.

a.log — Request logging

Wraps response writer in a statusRecorder to capture status code. Logs structured JSON: method, path, status, duration_ms. Implements Unwrap() so http.ResponseController can access underlying writer.

6.5 handlers_auth.go

POST /auth/register (public)

  • Validates: name not empty, email not empty, password ≥ 8 chars.
  • Hashes password with bcrypt cost 12.
  • Inserts user; handles unique constraint → 400 {"fields":{"email":"is already registered"}}.
  • Returns 201 with { token, user }.

POST /auth/login (public)

  • Looks up user by email; if not found → 401 (prevents enumeration).
  • Calls bcrypt.CompareHashAndPassword. Mismatch → 401.
  • Returns 200 with { token, user }.

issueToken

Creates JWT claims: user_id, email, exp: now + 24h. Signed with HS256.

6.8 handlers_sse.go — Server-Sent Events

Why ?token=? The browser's EventSource API cannot set custom headers, so the JWT is passed as a query parameter and verified server-side.
  1. Reads and verifies ?token= param via verifyToken().
  2. Calls canAccessProject — checks user's access rights.
  3. Uses http.NewResponseController to set write deadline to zero (infinite) for this connection only.
  4. Writes SSE headers: Content-Type: text/event-stream, Cache-Control: no-cache, X-Accel-Buffering: no.
  5. Subscribes to broker, sends initial : connected\n\n, flushes (fires browser's onopen).
  6. Event loop: forwards broker events, sends ping every 15 s, exits on client disconnect.

6.9 broker.go — SSE Event Broker

In-memory pub/sub that fans out task events to all connected SSE clients for a given project. 

type eventBroker struct {
    mu      sync.Mutex
    clients map[string]map[chan sseEvent]struct{}
    //       projectID → set of subscriber channels
}
  • subscribe: Creates a buffered channel (capacity 16), registers it for the project under mutex.
  • unsubscribe: Removes channel on disconnect (called via defer in SSE handler).
  • publish: Copies subscriber set under mutex, then sends to each channel with a non-blocking send — slow clients are silently skipped, never blocking the task handler.

export async function request<T>(path, options): Promise<T>
  • Sets Content-Type: application/json and Authorization: Bearer <token> if provided.

7.7 AuthContext.tsx — Auth State

Global React Context providing authentication to the whole tree. State is initialised from and persisted to localStorage (taskflow_token, taskflow_user).

  • login(email, password) → POST /auth/login, updates state + localStorage.
  • register(name, email, password) → POST /auth/register.
  • logout() → clears taskflow_token, taskflow_user, taskflow_dark; calls onLogout().

Context value is memoised with useMemo. useAuth() convenience hook throws if used outside AuthProvider.

7.17 ProjectDetailPage.tsx — Kanban Board

The most complex component. Key features:

  • URL filter state: useSearchParams stores status/assignee filters in the URL — filters survive refresh and are shareable.
  • SSE integration: useProjectEvents drives the ● Live badge and patches task state in real time.
  • Kanban grouping: Tasks split into three arrays by status; each rendered as a droppable column.
  • HTML5 Drag API: onDragStart stores taskId in dataTransfer; onDrop reads it and calls optimisticStatus.
  • Optimistic updates: Status change applied instantly in UI, then confirmed by API; reverted on error.
  • Parallel data load: Promise.all([GET /projects/{id}, GET /users]) on mount.
  • Two filter effects: One re-fetches on filter change, another on page change.

8.3 Real-Time SSE Update

Another user saves a task in the same project:

  Server: broker.publish(projectID, {Type:"task_updated", Data:task})
    for each subscriber channel: non-blocking send

  SSE handler loop:
    case ev := <-ch:
      json.Marshal(ev.Data) → b
      fmt.Fprintf(w, "event: task_updated\ndata: %s\n\n", b)
      rc.Flush()  ← immediate send

  Client (useProjectEvents):
    EventSource fires "task_updated" event
    JSON.parse(e.data) → Task
    onEventRef.current({ type:"task_updated", data:Task })

  ProjectDetailPage:
    setTasks(prev => prev.map(t => t.id===task.id ? task : t))
    // task card updates immediately in the Kanban board

8.4 Drag-and-Drop Status Change

User drags "Design homepage" from Todo → In Progress:

  handleDragStart(e, taskId)
    → e.dataTransfer.setData("taskId", taskId)

  handleDragOver(e, "in_progress")
    → e.preventDefault()         (required to allow drop)
    → setDragOverCol("in_progress")
    → CSS .column--drag-over applied → dashed green border

  handleDrop(e, "in_progress")
    → taskId = e.dataTransfer.getData("taskId")
    → optimisticStatus(task, "in_progress"):
        1. setTasks(map → status:"in_progress")  INSTANT
        2. PATCH /tasks/{id} {status:"in_progress"}
             → UPDATE tasks SET status=... RETURNING *
             → broker.publish → SSE to all other clients
        3. setTasks(map → server-confirmed task)
           (revert on error)

9 Security Design

Concern Implementation
Password storage bcrypt cost 12 — resistant to brute-force; never stored in plain text.
Authentication JWT HS256. Every protected request validates signature + performs DB user lookup.
Token expiry 24-hour exp claim.
SSE auth Token in ?token= (unavoidable with EventSource); fully verified server-side.
SQL injection All queries use parameterised statements ($1, $2…). Zero string concatenation of user input.
UUID validation All path params and IDs validated with uuid.Parse before use.
Input validation Enum allow-lists; date format check; length requirements.
Access control Every endpoint verifies the user's relationship to the resource.
CORS Currently * — fine for dev. Restrict to actual origin in production.
Privilege separation Backend runs as non-root appuser in Docker.
Graceful shutdown 10 s grace period prevents abrupt connection drops.
Log safety Logs only method, path, status, duration — no request bodies or tokens.
